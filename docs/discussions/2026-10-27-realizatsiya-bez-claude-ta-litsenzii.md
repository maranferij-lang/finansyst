# Як робити справжній продукт без Claude і чи потрібні ліцензії

Нотатки обговорення від 27.10.2026 (команда 3, StartUp Camp від Raiffeisen Bank). Це відповідь на питання Віки «які ліцензії, сервери й інші витрати потрібні на старті» (для аркуша «3. Гроші») і на питання «як реалізовувати продукт не через Claude». Усе, що не підтверджено джерелом, позначено як «оцінка» або «перевірити». **Це не юридична консультація**, перед запуском потрібен юрист.

## 1. Що означає «без Claude»

- Прототип (`index.html`, `web/index.html`) написано з Claude, але це звичайний код без збірки. Його читає й правит будь-який розробник. Контекст і рішення лежать у `CLAUDE.md` та `docs/discussions/`.
- У самому продукті **немає жодної залежності від ШІ**. Усе, що робить застосунок (поділ надходжень, прогноз, радар), це прості формули. Тож у справжньому продукті Claude потрібен лише як інструмент розробки, і його можна замінити будь-яким іншим (чи просто людьми).
- Якщо згодом додамо ШІ (наприклад, розпізнавання категорій у виписці), то сирі виписки клієнтів не можна відправляти стороннім моделям без згоди користувача й договору про обробку даних.

## 2. Ліцензії та дозволи

Що ми робимо, і чи потрібен на це дозвіл:

| Що робить продукт | Чи потрібна ліцензія | Статус |
|---|---|---|
| Віртуальні конверти, гроші лишаються на рахунку ФОП у банку, ми їх не тримаємо і не переказуємо | Ліцензія платіжної установи не потрібна, поки гроші не проходять через нас | Оцінка, юрист має підтвердити |
| Читати виписку ФОП автоматично через API банку (AISP) | Так: це нефінансова платіжна послуга, потрібна авторизація НБУ (включення до Реєстру платіжної інфраструктури) і страхування відповідальності | Правила діють з 01.08.2025 ([Положення про відкритий банкінг №80](https://bank.gov.ua/admin_uploads/law/25072025_80.pdf?v=14)). Для рахунків ФОП API ще не підтверджено |
| Ініціювати платіж із застосунку (PISP) | Так, та сама авторизація і страхування | Те саме |
| Лише готувати платіжну інструкцію, а підписує клієнт у банку (варіант А з [нотаток про оплату](2026-10-26-oplata-rozryvu-varianty-a-b.md)) | Імовірно, не потрібна, бо ми не ініціюємо платіж | Оцінка, перевірити з юристом |
| Показувати пропозицію овердрафту банку-партнера | Кредитує банк. Правила для кредитних посередників у законі про споживче кредитування стосуються споживчих кредитів фізосіб, для ФОП окремих правил не знайшли | Перевірити з юристом, перш ніж брати комісію від банку |
| Приймати оплату карткою через WayForPay, LiqPay | Ліцензії мають вони. Якщо використовуємо їхній готовий віджет і не бачимо номерів карток, вимоги стандарту PCI DSS на нас майже не лягають | Оцінка |
| Зберігати дані ФОП (телефон, виписка, баланси) | Закон про захист персональних даних: політика конфіденційності, згода, договори з підрядниками (хостинг, SMS) | Новий закон готують, чи ухвалено, не підтверджено. Чи треба реєструвати бази, перевірити |

Ключові числа за відкритим банкінгом (джерело: [НБУ про страхування AISP/PISP](https://psm7.com/uk/company/nbu/nbu-zatverdyv-poryadok-strahuvannya-u-systemi-vidkrytogo-bankingu.html), постанова №71 від 02.07.2025):
- мінімальна страхова сума з 01.08.2025: **€30 тис.** за один вид нефінансової послуги і **€50 тис.** за два види (AISP і PISP разом);
- далі її поетапно піднімають до рівня норм ЄС з **01.01.2027**;
- скільки коштує сам поліс (премія), невідомо, треба питати страхових брокерів.

Якщо ж колись захочемо **тримати гроші клієнтів або самі переказувати їх**, це вже фінансова платіжна послуга: платіжна установа, мінімальний капітал і нормативи НБУ ([огляд режиму](https://zib.com.ua/ua/print/152626.html)). У плани MVP це не входить.

НБУ (жовтень 2026) готує спрощення авторизації платіжних компаній, пропозиції приймає до 29 жовтня ([Mind](https://mind.ua/news/20311208-nbu-gotue-reformu-avtorizaciyi-platizhnih-kompanij-pershi-zmini-vinesli-na-obgovorennya)). Це варто відстежити.

## 3. Три щаблі без ліцензії і з нею

1. **Пілот без ліцензій.** Користувач сам завантажує виписку файлом, застосунок шукає регулярні платежі, платіжні інструкції готуємо, а підписує клієнт у банку. Платіжні дані й картки йдуть через WayForPay. Ліцензії не потрібні (оцінка).
2. **З банком-партнером (Raiffeisen).** Банк дає клієнту виписку як власні дані, а ми працюємо як партнер банку. Яка саме юридична схема, треба узгодити з банком. Це найбільш реалістичний шлях до автоматичної виписки для ФОП.
3. **Власна авторизація AISP/PISP.** Коли API для рахунків ФОП запрацює і ми будемо готові платити за страхування й супровід. Це найдорожчий і найдовший шлях.

## 4. Технічна основа замість прототипу

Це пропозиція (оцінка), а не рішення команди.

| Частина | Пропозиція | Навіщо |
|---|---|---|
| Інтерфейс | PWA лишаємо, переписуємо на TypeScript з React або Vue. Для магазинів застосунків обгортка (Capacitor) або React Native | Один код для браузера і телефона, як у прототипі |
| Сервер | Node.js (NestJS) або Python (Django/FastAPI) | У прототипі сервера немає, а для справжніх даних він обов'язковий |
| База | PostgreSQL, резервні копії щодня | Баланси, конверти, платежі, історія |
| Вхід | SMS-код (TurboSMS, Twilio Verify або Firebase Auth), згодом BankID | Зараз «будь-який код» тільки для демо |
| Фонові задачі | Черга (Redis) або cron: щоденне читання виписки, нагадування | Щоб дані оновлювались без участі користувача |
| Безпека | Шифрування токенів доступу, журнал дій, двофакторна автентифікація для команди, секрети в сховищі (не в коді) | Ми зберігаємо фінансові дані |
| Хостинг | AWS, Google Cloud або Hetzner, окремі середовища (тест і бойове) | Не ставити тестовий ключ WayForPay у бойове |
| Спостереження | Sentry (помилки), UptimeRobot (доступність), логи | Дізнаватись про збій раніше за користувача |
| Пошта і пуші | Postmark або Resend для листів, FCM і Web Push для сповіщень | Зараз лист лише показується на екрані |
| Інтеграції | WayForPay (договір), Checkbox, Нова пошта, Prom, Meta Marketing API (потребує перевірки застосунку Meta) | Зараз усе це захардкоджено |
| Облікові записи | Apple Developer (99 USD на рік), Google Play (25 USD один раз) | Публікація в магазинах застосунків |
| Командні інструменти | GitHub, Figma, Notion або Linear, Google Workspace | Безкоштовні або недорогі плани на старті |

## 5. Люди і приблизні статті витрат (оцінка, для аркуша «3. Гроші»)

Цифр з джерел тут немає, їх Віка бере з ринку (Djinni, DOU, комерційні пропозиції).

- **Команда для пілота:** 1 бекенд-розробник, 1 фронтенд або мобільний, дизайнер на частку ставки, Віка як продукт, DevOps і безпека на частку ставки. Приблизний строк пілота: 3–4 місяці (оцінка).
- **Юрист** на гонорарі: політика конфіденційності, договір-оферта, висновок щодо схем із банком.
- **Бухгалтер** і реєстрація компанії (ТОВ або ФОП). Варіант: статус Дія.Сіті, умови на 2026 рік не підтверджено.
- **Фіксовані щомісячні:** хостинг, SMS, пошта, моніторинг (десятки доларів на старті, оцінка), підписки на інструменти.
- **Окремо потім:** страхування відповідальності для AISP/PISP (мінімум €30–50 тис. страхової суми, премія невідома), аудит безпеки, ліцензії й сертифікати для доступу до API банку.

## 6. Як говорити на пітчі

Можна казати:
- «Конверти віртуальні, гроші лишаються на рахунку ФОП у банку, тому нам не потрібна ліцензія платіжної установи».
- «Читання виписки напряму з банку регулюється відкритим банкінгом НБУ і потребує авторизації та страхування. Ми розглядаємо це разом із банком-партнером».
- «У продукті немає залежності від ШІ: правила прозорі й перевіряються».

Не можна казати:
- «Ліцензія нам точно не потрібна»: без юриста це лише оцінка.
- «Ми вже підключені до API банку».

## 7. Що перевірити далі

1. Юрист: чи потрібна нам авторизація для схеми «готуємо інструкцію, підписує банк», і яка схема допустима для комісії від банку за овердрафт.
2. Банк і наставники Raiffeisen: чи може банк віддавати виписку клієнта-ФОП партнеру і за якою схемою; коли відкриють API для ФОП.
3. Страхові брокери: вартість полісу для AISP і PISP.
4. Закон про захист персональних даних: чи треба реєструвати бази, чи ухвалено новий закон.
5. Статус компанії: ТОВ чи ФОП, Дія.Сіті, податки на підписку (800 ₴/міс у фінансовій таблиці), чи потрібен РРО для приймання оплат.
